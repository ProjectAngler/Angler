## Dependency and recovered-code rule

No external or recovered code gains authority from familiarity or recovery effort. Before adoption, record the demonstrated interface need, source and exact version/commit, license, provenance, trust and security review, fit, tests, modification boundary, maintenance/upgrade plan, and exit/replacement path. Until that intake passes, candidate code remains quarantined and outside the build.

The public dependency and research-origin inventory is maintained in
`THIRD_PARTY_NOTICES.md`. It identifies the one declared equation-level code
adaptation, preserves its MIT notice, distinguishes installed dependencies from
vendored code, records the exact Qwen model revision used locally, and separates
independent paper-level implementations from reference-only future donors.
