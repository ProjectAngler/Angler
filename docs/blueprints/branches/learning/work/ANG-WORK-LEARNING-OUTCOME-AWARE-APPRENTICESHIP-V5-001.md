# ANG-WORK-LEARNING-OUTCOME-AWARE-APPRENTICESHIP-V5-001

Status: specified; implementation is the next active frontier

Active node: `ANG-BP-LEARNING` / experimental meta-updater successor

Assurance: LOW; local synthetic software episodes, frozen foundation, no
deployment or external effects

## Evidence-driven need

Autonomous runtime V1, V2, V3, and V4-R1 are preserved negative results. The
final result SHA-256 is
`226E92BDA20DFA942B2DB4DEDA6CEE7124A5BCABDF9278EEBBC425FC75BF5123`.
The runtime can now clarify before mutation, act in a rooted workspace, receive
objective diagnostics, retry, retain bounded procedures in Cognee, situate
them with Moving Origin, persist plastic state atomically, and replay exact
state after restart. Nevertheless the inherited V6 action-trace core harms
performance versus reset/removal controls and never produced a failed-to-pass
repair.

V6 was trained only on `+1` successful support traces from a synthetic pipeline
domain. It was never trained to interpret mixed success/failure coding
episodes or to make negative feedback reduce future failed-procedure use. The
runtime must not compensate with task rules, prompt tuning, or a hard-coded
success bias.

## Accountable outcome

Train a learned outcome-aware procedural core that consumes a chronological
stream of natural-language task, bounded action trace, objective outcome, and
Moving-Origin coordinates. Its persistent state must make a relevant
successful procedure more usable on a fresh structural variant while making a
relevant failed procedure less likely to be repeated. The same learned update
rule must process `+1` and `-1`; no procedure is selected by deterministic
outcome filtering.

Use the already established OML direction: an inner chronological episode
stream updates only one bounded plastic state; an outer objective scores
held-out variants after the update. ANML-style learned gating is allowed only
as a predeclared control/successor if the OML core shows interference at scale,
not as an automatic rescue.

## Data and leakage boundary

- Training uses fresh generated disposable software episodes spanning at least
  32 mechanisms and multiple surface/action variations, with both successful
  and plausible failed procedures.
- Development and final mechanisms are generator-disjoint, not merely renamed
  instances. Final identities remain sealed from gradients and threshold
  changes.
- Frozen Qwen provides detached text/action embeddings only; foundation weights
  never change.
- Deterministic code may generate tasks, execute/judge procedures, package
  tensors, and measure outcomes. It may not encode mechanism IDs, expected
  procedure indices, solution templates, verifier answers, generator seeds,
  or event IDs as learner features.
- Cognee remains disposable candidate retrieval; canonical episodes and the
  neural state remain separate. Moving Origin supplies declared temporal
  coordinates, not a hand-coded recency preference.

## Intended learned mechanism

Extend the action-trace core with learned outcome conditioning in both its
write rule and candidate scoring. Candidate inputs include detached semantic
features, declared temporal features, and an outcome token learned from the
training stream. The core must learn whether and how outcome affects writes;
the runtime does not partition or reorder candidates by outcome. OML outer loss
contains:

1. held-out procedure usefulness/execution after chronological updates;
2. pairwise preference for relevant successful evidence over relevant failed
   and irrelevant evidence;
3. explicit anti-repetition loss for a failed trace on a fresh variant;
4. retention on earlier acquired mechanisms without replaying every history;
5. bounded state magnitude and finite update checks.

## Frozen acceptance

Before final evaluation, freeze exact corpus generators, partitions, seeds,
compute budget, thresholds, and controls. A supported result requires:

- held-out full success at least 0.70 across at least eight final mechanisms;
- at least +0.15 over state reset, outcome shuffled, memory disabled, fair
  semantic retrieval, and Moving-Origin-removed controls under equal inputs;
- at least one failed-to-pass repair on a fresh variant without user grading;
- negative feedback reduces repeat probability of the failed procedure while
  preserving or increasing access to a successful alternative;
- zeroing/removing learned plastic state erases the gain and state swap
  transfers it to an equivalent fresh runtime;
- sequential retention remains within the predeclared bound without full
  history replay per update;
- frozen Qwen and all non-plastic core parameters are byte-exact before/after;
- first valid result is accepted without seed retry or post-result tuning.

Passing establishes an outcome-aware bounded apprenticeship core in synthetic
software worlds. It does not establish arbitrary-project autonomy,
cross-domain intelligence, consciousness, AGI, deployment safety, or final
Angler readiness.

## Stop and rollback

Stop on leakage, non-finite state/gradients, hidden-final access, result reuse,
foundation mutation, threshold adaptation, deterministic solution logic,
scope expansion, or evidence failure. Preserve every valid or failed terminal
result. Roll back only this leaf's fresh code and restore the exact parent
checkpoint; never overwrite prior evidence.
